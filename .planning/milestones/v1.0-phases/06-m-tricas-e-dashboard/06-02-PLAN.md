## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser real (executa JS) vs. crawler de unfurling (não executa JS) | O disparo client-side no `useEffect` separa visitante humano de bot de preview — só o primeiro monta o tracker |
| Client Component → Server Action pública | `logPageview` roda com o papel `anon`; a proteção contra dado inconsistente é a RLS `WITH CHECK` de 06-01, não o código do tracker |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-05 | Tampering | inflação de "mais visualizados" por crawlers (WhatsApp/Facebook fazem GET real na página de produto com Open Graph da Fase 5) | medium | mitigate | disparo em `useEffect` client-side (Task 2), nunca no corpo do Server Component — crawlers não executam JS e nunca montam o tracker (Pitfall 2) |
| T-06-06 | Information Disclosure | `storeId` exposto ao cliente no prop do tracker | low | accept | `store_id` é um UUID não-secreto, já necessário para o insert e já exposto de forma equivalente em `logOrderClick` desde a Fase 5; a RLS é a fronteira de segurança real |
| T-06-07 | Spoofing | rota pública ganhar acidentalmente um gate de auth ao introduzir o layout | high | mitigate | o novo `layout.tsx` só resolve `store_id` e monta o tracker; sem `redirect`/`getUser`-gate — verificado por acceptance criteria (ausência de gate) |
